01 / Overview

개요

문제 — 놀 거리를 찾을 때 장소 검색, 친구와 일정 맞추기, 다녀온 기록이 여러 앱에 흩어져 있다.

목표 — 열면 바로 주변 놀 거리를 추천하고, 친구와 투표로 갈 곳을 정하고, 놀이 기록과 축제 도장을 모으는 서비스를 웹과 앱에서 똑같이 제공한다.

02 / My Role

내 역할 — 팀이 한 일과 내가 한 일

팀 성과를 내 성과로 적지 않도록, 담당 범위를 나눠 적었습니다.

영역팀(주로 팀장)나
화면웹(Blazor Web App) 화면과 디자인앱 화면 전체 — 웹 기능을 앱으로 옮기고 휴대폰에 맞게 배치

서버·DBAPI·DB 설계와 구현, AWS 배포앱의 API 연동, 앱 버전 확인 API 추가, 인증 방식 변경에 맞춘 앱 수정
배포웹 배포(EC2), 릴리스 관리앱 Release APK·AAB 빌드, 버전 규칙
문서요구사항·아키텍처·API 명세학교 AWS 계정 설정 순서(docs/09-2), 앱 관련 API 명세 보완

03 / Architecture

구조 — 요청이 지나가는 길과 각자의 책임

3.1요청 흐름 — 장소 추천

  1. 사용자가 앱에서 'PC방' 필터를 누르면, 앱이 기기 GPS로 현재 위치를 읽는다(지도에서 직접 정한 위치가 있으면 그것을 쓴다).
  2. 앱은 공용 API 클라이언트(JamBox.Shared)로 위치·분류·반경을 API에 보낸다.
  3. API는 서버에만 있는 키로 카카오 로컬 API를 불러 주변 장소를 찾고, 거리순으로 돌려준다.
  4. 앱은 목록을 그리고, JS interop으로 네이버 지도에 번호 마커를 찍는다. 마커를 누르면 .NET으로 알려 목록의 그 장소로 스크롤한다.

04 / Database

DB — 앱이 쓰는 테이블과 제약

DB 설계는 팀장이 했고, 나는 앱에서 이 테이블들을 쓰는 화면을 만들었습니다. 테이블은 API가 처음 켜질 때 schema.sql로 자동 생성됩니다.

제약앱에서 어떻게 드러나는가
poll_votes (poll_id, voter_hash) 기본 키로그인 없이 투표해도 한 기기는 한 표만 — 앱은 기기마다 만든 투표자 키를 보관하고, 다시 투표하면 표가 바뀐다
festival_stamps (user_id, festival_id) 기본 키한 축제에 도장은 한 번 — 이미 찍은 축제는 상세 화면에 '도장 찍음 · 날짜'로 보인다
poll_options → polls ON DELETE CASCADE투표를 지우면 후보와 표도 함께 지워져, 앱 목록에 빈 후보가 남지 않는다
journal_entries rating 1~5, memo 500자 제한앱 양식도 별점 5개·메모 글자 수(남은 글자 표시)로 같은 범위를 지켜, 서버 오류 전에 막는다

05 / API Design

API — 내가 추가한 계약과 앱의 호출 규칙

GET/api/app-version

200 OK
{
  "latest": "0.9.2",
  "downloadUrl": ""
}
  • 값은 서버 설정 AppVersion:Latest·DownloadUrl에서 읽는다 — 새 APK를 내면 앱 수정 없이 서버 값만 바꾼다.
  • 앱은 켜질 때 한 번 부르고, 5초 안에 답이 없거나 실패하면 조용히 넘어간다(앱 사용을 막지 않음).
  • 버전은 문자열이 아니라 숫자로 비교한다(0.9.2 < 0.10.0).

로그인 토큰으로 본인 확인하는 호출

GET /api/auth/me
Authorization: Bearer <access token>

200 → 내 계정 정보
401 → 토큰 갱신 후 한 번 더
      그래도 401이면 로그아웃
  • 보안을 위해 '사용자 id를 보내 조회'하던 방식이 '토큰으로 본인 확인'으로 바뀌었고, 앱의 모든 본인 전용 호출을 한 함수로 감쌌다.
  • SNS로 처음 가입한 사람은 추가 정보를 입력할 때까지 로그인 상태로 두지 않는다(가입 대기).

API 전체 명세(인증·장소 추천·투표·도장 등)는 저장소 docs/04-API명세서.md에 있습니다. 서버 대부분은 팀장이 구현했습니다.

06 / Trade-off

기술 결정 — 무엇을 왜 골랐나

안드로이드 뒤로가기: 펼친 것부터 닫고, 그다음 화면 이동

상황
앱은 화면 전체가 WebView 하나라서, 기본 동작으로는 뒤로가기를 누르면 화면 이동 없이 앱이 바로 꺼졌다.
대안
① 브라우저 기록만 되돌리기 — 팁 카드·필터 창이 열려 있어도 화면이 넘어가 버림 ② 화면마다 따로 처리 — 중복이 많고 빠뜨리기 쉬움
선택
펼친 것(팁·필터·펼친 목록·팝업)이 스스로 '닫기'를 등록하고, 나중에 열린 것부터 닫는다. 닫을 게 없으면 탭 화면은 홈으로, 그 밖은 이전 화면으로. 홈에서는 두 번 눌러야 앱이 뒤로 간다.

업데이트 안내: 기준 버전을 서버 설정에 둔다

상황
새 APK가 나와도 사용자가 알 방법이 없었다.
대안
GitHub Releases에서 최신 태그를 읽기 — 확인해 보니 저장소의 릴리스 API가 공개 응답을 주지 않아(404) 쓸 수 없었다.
선택
API에 버전 엔드포인트를 두고 서버 설정값을 돌려준다. 팀장이 배포할 때 값만 바꾸면 되고, 서버가 꺼져 있어도 앱은 평소처럼 동작한다.

화면 팁: 자동 팝업 → 하루 숨기기 → 눌러야 열림

상황
화면을 옮길 때마다 AI 팁이 저절로 떠서 직접 써 보니 거슬렸다.
1차
'하루 동안 보지 않기' 체크박스를 추가(10.20).
2차
팀원 의견으로 저절로 뜨는 것 자체를 없애고 전구 버튼을 눌렀을 때만 그 화면 팁을 불러오게 했다(11.16). 필요 없어진 체크박스는 지웠다.

SNS 로그인: 카카오는 앱 안 WebView, 구글은 시스템 브라우저

상황
같은 방식으로는 구글 로그인 페이지가 열리지 않았다(구글은 앱 내장 WebView 로그인을 정책상 막는다).
선택
구글만 휴대폰 기본 브라우저(WebAuthenticator)로 열고, 끝나면 jambox://auth-callback 주소로 앱에 돌아오게 했다.

07 / Troubleshooting

트러블슈팅 — 해결이 아니라 검증까지

모든 사례를 증상 → 원인 → 결정 → 검증 순서로 적었습니다. 검증하지 못한 것은 못 했다고 적었습니다.

Windows 앱에서 버전이 '1.0.0.1'로 표시됨

SYMPTOM
앱 버전을 0.9.x로 올렸는데 마이 화면에는 1.0.0.1이 나왔다.
CAUSE
Windows 앱을 패키지 없이 실행하면 앱 정보가 매니페스트 기본값을 읽는다. Android는 정상.
DECISION
Windows에서만 프로젝트 버전이 들어가는 어셈블리 버전을 읽도록 분기.
VALIDATION
원격 디버깅으로 마이 화면 문구를 읽어 '앱 버전 0.9.1' 확인, APK도 versionName 0.9.2 확인(aapt).

안드로이드에서 뒤로가기를 누르면 앱이 꺼짐

SYMPTOM
팀원 제보 — 어느 화면에서든 뒤로가기 한 번에 앱이 종료.
CAUSE
MAUI 기본 동작이 WebView 안의 화면 기록을 모른 채 앱을 닫는다.
DECISION
뒤로가기를 앱 화면에 넘기는 처리기 추가(06 기술 결정 참고). 일지 작성 중엔 입력을 지키려고 화면을 벗어나지 않는다.
VALIDATION
Android 빌드 경고·오류 0. 실제 휴대폰 확인은 아직 — 이 PC의 에뮬레이터가 켜지지 않아 실제 기기 확인이 남아 있다.

팀장 브랜치를 병합하자 앱 빌드가 깨짐

SYMPTOM
공용 인증 클라이언트의 메서드가 사라져 앱이 컴파일되지 않았다.
CAUSE
보안 강화로 내 정보 조회가 토큰 기반으로 바뀌고 반환 형식도 달라졌다.
DECISION
모든 호출 부분을 토큰 방식으로 바꾸고, SNS 가입 대기·중복 가입 안내를 추가.
VALIDATION
앱 빌드 통과 확인. 이후 '병합 직후 앱 빌드'를 내 작업 규칙으로 삼았다.

지도에 추천 장소가 아무것도 안 보임

SYMPTOM
장소 추천 화면의 지도와 목록이 비어 있었다.
CAUSE
네이버 지도는 등록한 주소에서만 인증된다. 웹이 등록하지 않은 포트(5288)로 실행돼 인증 실패.
DECISION
웹을 등록 주소의 포트 5080으로 실행. 앱은 WebView 주소(https://0.0.0.0·0.0.0.1)가 서비스 URL에 등록돼 있는지 확인.
VALIDATION
지도와 장소 목록 표시 확인. 팀장이 5080을 웹 기본 설정으로 반영했다.

로그인과 모든 데이터 기능이 한꺼번에 멈춤

SYMPTOM
로그인·일지·투표가 모두 실패. 코드는 바뀐 게 없었다.
CAUSE
DNS 조회 결과 Supabase 프로젝트 주소가 '존재하지 않음' — 무료 플랜 프로젝트가 일시 정지됐다.
DECISION
코드를 고치지 않고 팀장에게 프로젝트 복구를 요청.
VALIDATION
복구 후 API를 하나씩 호출 — 장소·축제 200, 틀린 비밀번호 401로 정상 동작 확인.

학교 AWS 계정에서 접근 키를 만들 수 없음

SYMPTOM
사진을 S3에 올리려면 IAM 접근 키가 필요한데, 학교 계정은 발급·IAM 사용자 생성이 막혀 있었다.
CAUSE
미리 정해 둔 IAM 역할만 쓰도록 제한된 계정 정책.
DECISION
코드를 확인해 키를 비우면 서버의 IAM 역할로 S3에 접근함을 이용 — EC2에는 인스턴스 프로필, 개발 PC는 DB만 RDS.
VALIDATION
설정 순서를 팀 문서(docs/09-2)로 남겨 main에 반영. 이후 팀은 AWS(EC2·RDS·S3)로 배포를 마쳤다.

08 / Test · Deploy

테스트와 배포 — 내가 실제로 확인한 방법

  1. Branch내 브랜치에서 작업, 팀장 브랜치 먼저 병합
  2. BuildWindows·Android 둘 다 빌드, 경고·오류 0 확인
  3. CheckWindows 앱을 원격 디버깅으로 휴대폰 크기(390×844)로 띄워 화면 조작·캡처
  4. Release서명된 Release APK·AAB 빌드, 앱 이름·버전 확인(aapt)
  5. Share배포 폴더 교체·커밋, PR로 main 반영 → 팀장 릴리스

업데이트 팝업 검증 — 로컬 API를 최신 버전 0.9.2로 설정해 켜고, 0.9.1 앱을 실행해 팝업이 뜨는지, '나중에'로 닫히는지 확인했습니다.

같은 방법으로 팁이 저절로 뜨지 않는 것, 마이 화면 버전 표시, 목록을 끌어 올리고 내리는 동작(320px 끌기 → 펼침, 20px → 그대로)을 확인했습니다.

자동 테스트와 CI는 아직 없습니다. 검증은 위처럼 직접 조작해 확인한 범위입니다. 측정한 성능 수치도 없어 적지 않았습니다.

09 / Retrospective
